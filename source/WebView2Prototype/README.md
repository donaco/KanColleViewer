# WebView2 比較試作

このプロジェクトは段階1の検証専用です。本番アプリのブラウザー実装・設定・配布には接続していません。標準 WPF WebView2 と Evergreen Runtime を使い、専用のユーザーデータフォルダー `LocalAppData\Grabacr07\KanColleViewer\WebView2Prototype` に保存します。CEF のユーザーデータは参照・変更しません。

## 検証できること

- ゲームページの表示、戻る/進む/更新、標準 WPF WebView2 の入力・スクロール
- FPS モード: 既定動作（FPS保証なし）、`--disable-frame-rate-limit` による上限解除（効果未検証）。30 / 60 FPS固定は未対応と表示し、選択できません
- `--disable-gpu` の起動引数
- ゲーム URL の `/kcs2/index.php` iframe のみを対象にした CDP 撮影（PNG/JPEG、1200×720 px を検証）。ページ直下と `game_frame` 内の入れ子に対応し、外側の1200×860領域ではなく内側のゲーム領域を特定します
- 正規ゲームサーバーの `/kcsapi/` 応答本文取得。要求/応答本文は 5 MiB まで読み取り、内容を画面表示・ログ出力・ファイル保存せず、本文長と取得可否のみを記録
- 既存 `KanColleServerOrigin.IsValid` による HTTPS ゲームサーバーの検証

倍率変更はブラウザーの表示倍率のみを変更します。アプリサイズとの連動、およびDMMのヘッダー・余白などを隠してゲームだけを表示するCSSは未実装で、移行計画の段階4で対応します。

`Emulation.setScrollbarsHidden` だけでは左端の白帯が改善しませんでしたが、一時CSS方式への変更後は利用者が解消を確認しました。

ゲーム通信の再送・改変や解析側への配送は行いません。

## 段階1の確認結果（2026-11-02）

- ゲームの表示と倍率変更を確認しました。アプリサイズとの連動は未実装です。
- 利用者より、FPS選択の表示・初期化後の設定ロック、ゲーム内のクリック・日本語入力・スクロール・ドラッグ、別アプリからの復帰、ウィンドウの縮小・拡大に異常なしと報告されました。
- 50% / 100% / 150%での入力位置、PNG/JPEGの1200×720撮影、白帯・欠け・黒画像がないこと、撮影後のスクロールに異常なしと利用者から報告されました。異なるWindows DPI設定での確認は未完了です。
- 応答本文の取得は、画像内のログで `api_start2/getdata`（2,345,472 bytes）、`api_port/port`、`api_get_member/require_info` などを確認しました。要求本文は seek 非対応のため未取得で、通信キャプチャ全体の合格とはしていません。
- 再起動後に「GPUを無効化（起動引数）」を選んだ条件で、母港の描画・クリックが正常なことを利用者が確認しました。試作が所有する実行中のWebView2ブラウザープロセスに `--disable-gpu` が渡っていることも確認しました。ゲームのcanvasからはWebGLコンテキストを取得できず、描画方式は特定できませんでした。この結果だけではGPU無効化の成功・失敗やCanvas 2Dの使用を断定しません。ハードウェア描画が実際に無効になったこと、戦闘時の動作・負荷は未確認です。
- 60HzモニターでDevToolsのFrame Rendering Statsを再測定した結果、既定30～50、60 FPS固定（未対応・検証のみ）30～50、上限解除30～45と報告されました。先の31.8という単一値ではなく、この再測定を記録します。ゲーム外の変化に数値が反応する一方、ゲーム内操作では変化が見られないため、これらはゲーム本体の描画FPSの測定結果としては採用しません。固定の成否や上限解除の効果も判定できません。
- 試作の「60 FPS固定」は固定処理を実装しておらず、起動引数も既定と同じです。上限解除だけが `--disable-frame-rate-limit` を追加します。設定名や上記の表示値を根拠に、固定・モニター同期・上限解除の成立を保証しません。
- 利用者の承認により、30 / 60 FPS固定は未対応と明示し、既定動作と上限解除（効果未検証）で段階1の検証を継続する方針に決定しました。CEF版にある固定FPSをWebView2試作では提供しません。ゲームの更新ロジックやrequestAnimationFrameの書き換えは行いません。
- 追加したWPF Popupについて、ゲーム前面への表示、日本語入力、項目A/B/Cの選択、背後への操作透過がないこと、閉じるボタンと外側クリックによる終了、その後のゲーム操作の全項目に問題なしと利用者から報告されました。本番のランチャー・各ドック配置・分割ウィンドウの回帰確認は別途必要です。
グリップが最下部の説明バー内にありゲーム・情報欄に重ならないことも、説明後に利用者が問題なしと確認しました。
- 配置・分割・グリップの追加後、利用者側でビルド成功と実機確認完了の報告を受けました。

## 段階1の判断と引き継ぎ

利用者の承認により、以下の制約を残して段階1を区切ります。段階1のコミットを確認してから段階2の本移植へ進みます。

- 描画方式: 標準WPF WebView2を採用候補とします。今回の基本操作・Popup・配置検証では阻害要因が見つからなかったため、現時点でComposition版の比較は行いません。本番への組み込み後も回帰確認が必要です。
- FPS: 30 / 60 FPS固定は未対応です。既定動作と上限解除（効果未検証）を検証対象にします。既存の固定FPS設定の移行・説明は段階2で扱います。
- GPU無効: 引数の指定と母港の基本操作は確認済みです。ハードウェア描画の無効化や負荷低減は保証せず、描画方式・戦闘時の動作は未検証として引き継ぎます。
- 通信: 応答本文取得の成立のみを確認済みです。要求本文の非seekストリーム対応、解析への配送、例外時の扱いは段階3で実装・検証します。
- レイアウト: 本番CSS、倍率と表示領域の連動、本番の各ドック配置・分割・追従・バー表示切替、異なるWindows DPI設定は段階4で実装・検証します。
- 比較条件: モニターは60Hzです。Evergreen Runtimeのバージョン、Windows/DPIなどの環境条件と性能比較は未記録で、配布判断までに記録・検証する必要があります。今回の試作成功を本移植完了や性能改善の証明とはしません。

## 配置・分割・グリップの確認

1. ゲームを表示し、「情報欄の配置」を下/上/左/右に切り替えます。ログとゲームが重ならず、クリック位置が一致し、ログの更新が続くことを確認します。ゲーム全体が収まらないときは倍率を50%にしてください。
2. 各配置で「Popup検証」を開き、ゲームの前面へ表示されること、閉じた後もゲームを操作できることを確認します。
3. 「情報欄を分割」でログだけが別ウィンドウになること、ゲームが再読み込みされず、両方を操作できることを確認します。
4. 「情報欄を結合」と、別ウィンドウの×ボタンの両方で元の配置へ戻せることを確認します。分割/結合を数回繰り返し、ログが消えず更新されることを確認します。
5. 最大化していない状態で、ウィンドウ右下のサイズ変更用の斜線（グリップ）をドラッグします。斜線が最下部の説明バー内にあり、ゲーム画像やログの上には載っていないことと、ドラッグ中にゲームを誤操作しないことを確認します。ウィンドウの外枠からのサイズ変更だけでは、この重なりの確認にはなりません。最大化/元に戻す、最小化/復帰も確認します。
6. 情報欄を分割したままメインを終了し、情報欄のウィンドウも終了することを確認します。この試作での合格は本番レイアウトの回帰確認を代替しません。

## 起動と基本確認

1. Visual Studio で `source\WebView2Prototype\WebView2Prototype.csproj` を開きます。
2. ビルド後に起動し、FPS/GPU の起動条件を選んで「初期化して移動」を押します。起動引数は環境作成時に固定されるため、別条件を試す際はアプリを終了して再起動してください。
3. 必要に応じてゲームへログインし、描画、クリック、ホイール、スクロールを確認します。
4. 50%/100%/150% の倍率でゲーム画面を PNG/JPEG 撮影し、画像プロパティが毎回 1200×720 px であることを確認します。ページ先頭とスクロール後の両方で、白帯・位置ずれ・欠けがないことも確認します。撮影座標はトップページのスクロール量を含む文書座標へ変換し、指定ゲーム領域はビューポート外も撮影します。ゲーム iframe が特定できない場合、ページ全体を代替保存せずエラーにします。
5. API 通信時にログへ URL パス、メソッド、応答コード、本文サイズ、5 MiB 上限、取得失敗が記録されることを確認します。本文は表示も永続化もしません。
6. 30 / 60 FPS固定が選択できないことを確認します。既定動作・上限解除とも、DevToolsのFrame Rendering Statsの数値だけでゲーム本体の描画FPSや起動引数の効果を判定しないでください。
7. GPU 無効時の WebGL、黒画面、操作性を確認します。
8. ゲームを表示し、「Popup検証」を押します。パネルがゲームの前面に表示され、日本語入力と検証項目A/B/Cの選択ができることを確認します。「閉じてゲームへ戻る」で閉じた後、ゲームを操作できることを確認します。再度開き、パネル外のゲーム部分の安全な場所をクリックして閉じることと、その後のゲーム操作を確認します。パネル内の操作が背後のゲームへ伝わらないことも確認してください。この試験は本番のランチャー・各ドック配置・分割ウィンドウの回帰確認を代替しません。

検証を行う環境の Evergreen Runtime バージョン、Windows/DPI/モニターリフレッシュレート、結果と未実施項目を移行計画の段階1に記録してください。Runtime 不足時は Runtime を導入してから再試行します。自動インストールは行いません。
