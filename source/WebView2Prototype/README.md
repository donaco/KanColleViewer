# WebView2 比較試作

このプロジェクトは段階1の検証専用です。本番アプリのブラウザー実装・設定・配布には接続していません。標準 WPF WebView2 と Evergreen Runtime を使い、専用のユーザーデータフォルダー `LocalAppData\Grabacr07\KanColleViewer\WebView2Prototype` に保存します。CEF のユーザーデータは参照・変更しません。

## 検証できること

- ゲームページの表示、戻る/進む/更新、標準 WPF WebView2 の入力・スクロール
- FPS モード: 既定のモニター同期、公開 API の有無を調べる 60 FPS 固定（機能を保証しない）、`--disable-frame-rate-limit` による上限解除
- `--disable-gpu` の起動引数
- ゲーム URL の `/kcs2/index.php` iframe のみを対象にした CDP 撮影（PNG/JPEG、1200×720 px を検証）。ページ直下と `game_frame` 内の入れ子に対応し、外側の1200×860領域ではなく内側のゲーム領域を特定します
- 正規ゲームサーバーの `/kcsapi/` 応答本文取得。要求/応答本文は 5 MiB まで読み取り、内容を画面表示・ログ出力・ファイル保存せず、本文長と取得可否のみを記録
- 既存 `KanColleServerOrigin.IsValid` による HTTPS ゲームサーバーの検証

倍率変更はブラウザーの表示倍率のみを変更します。アプリサイズとの連動、およびDMMのヘッダー・余白などを隠してゲームだけを表示するCSSは未実装で、移行計画の段階4で対応します。

撮影時はトップページに一時CSSを追加してスクロールバーの占有幅をなくし、レイアウト更新後に座標を取得します。撮影後は追加したCSSだけを削除します。これは `captureBeyondViewport` が撮影時にスクロールバーを隠すことで中央寄せ位置が変わるのを防ぐための対策です。`Emulation.setScrollbarsHidden` だけでは左端の白帯が改善しなかったため、この方式の効果は実機で再確認が必要です。左右の白帯・欠けがないことと、撮影後に通常どおりスクロールできることを確認してください。

ゲーム通信の再送・改変や解析側への配送は行いません。

## 起動と基本確認

1. Visual Studio で `source\WebView2Prototype\WebView2Prototype.csproj` を開きます。
2. ビルド後に起動し、FPS/GPU の起動条件を選んで「初期化して移動」を押します。起動引数は環境作成時に固定されるため、別条件を試す際はアプリを終了して再起動してください。
3. 必要に応じてゲームへログインし、描画、クリック、ホイール、スクロールを確認します。
4. 50%/100%/150% の倍率でゲーム画面を PNG/JPEG 撮影し、画像プロパティが毎回 1200×720 px であることを確認します。ページ先頭とスクロール後の両方で、白帯・位置ずれ・欠けがないことも確認します。撮影座標はトップページのスクロール量を含む文書座標へ変換し、指定ゲーム領域はビューポート外も撮影します。ゲーム iframe が特定できない場合、ページ全体を代替保存せずエラーにします。
5. API 通信時にログへ URL パス、メソッド、応答コード、本文サイズ、5 MiB 上限、取得失敗が記録されることを確認します。本文は表示も永続化もしません。
6. 60 FPS 固定は選択しても固定されるとは限りません。
7. GPU 無効時の WebGL、黒画面、操作性を確認します。設定は起動時引数だけで切り替わります。

検証を行う環境の Evergreen Runtime バージョン、Windows/DPI/モニターリフレッシュレート、結果と未実施項目を移行計画の段階1に記録してください。Runtime 不足時は Runtime を導入してから再試行します。自動インストールは行いません。
